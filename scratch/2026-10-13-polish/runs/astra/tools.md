# 실제 작업에서 만난 도구의 아쉬움

## 접지 상태를 표현하는 입력과 수리가 없다 — rig-pose
- **하려던 것:** 고정 길이 다리로 춤을 옮겨도 지지 발이 바닥을 따라 떠다니지 않게 하고, 점프는 보존하려 했다.
- **도구가 준 것:** @rig-c/pose README `What 0.1.0 does not do`: “Plant feet beyond what the pose gives”. 입력 report는 관절각·fold를 주지만 접지 구간/바닥 높이 목표는 없다.
- **있었으면 했던 것:** `contacts`에 지지 발·프레임·바닥·허용 오차를 선언하고, 도달 불가능한 구간은 이름으로 거부하는 수리/측정 명령. 양발 잠금과 airborne를 구분해야 한다.
- **비용:** 전체 진단·수리 구간 중 대략 2분과 로컬 스크립트. 최소 신발 바닥 수직 보정은 했지만 양발 IK·수평 잠금은 못 했다. 반대 발 높이 차이 22.93단위가 남는다.

## 투명 다리 연결을 끊은 뒤 분할까지 수작업이다 — rigc
- **하려던 것:** 두 다리 사이에서 접히는, 완전히 투명한 연결 삼각형 둘을 없애려 했다.
- **도구가 준 것:** build는 `the triangles' outline is not one closed loop: the walk from vertex 0 closes after 64 of 126 boundary vertices (see rigc guide §5.1)`라고 정확히 거부했다. AUTHORING §3.4는 “hull vertices must come first”와 경계 walk 순서를 설명한다.
- **있었으면 했던 것:** 독립 연결 성분별 mesh/slot 분할 제안 또는 UV·weights·triangles·deform까지 함께 재번호화하는 명령. 허용하지 않는 구조를 통과시키는 옵션은 필요 없다.
- **비용:** 실패 1회, 분할 스크립트 1개, 재빌드 1회, 대략 1분. 각각 218·224삼각형의 두 메시로 나눠 해결했다.

## 전후 렌더의 고정 월드 뷰포트를 지정할 수 없다 — rigc
- **하려던 것:** 접지·치마 변경을 동일 좌표와 배율에서 비교하고 기존과 같은 648×480 데모를 만들려 했다.
- **도구가 준 것:** render --help는 `--max <px>`와 `--geometry`를 제공한다. 실제 입력은 377×480, 수정본은 385×480으로 자동 fit됐다. `frames.json.viewport`가 정확한 좌표를 제공하는 점은 유용했다.
- **있었으면 했던 것:** `--viewport-from <frames.json>` 또는 명시적인 월드 박스 옵션. 박스 밖으로 나간 부위는 경고해 주면 된다.
- **비용:** 공통 좌표 변환과 합성 스크립트 1개, 대략 2분. viewport 합집합과 동일 scale로 해결했다.

## 리타깃이 놓친 보조 표정 트랙을 알기 어렵다 — rig-pose
- **하려던 것:** 춤 동작을 재생하면서 입력 리그에 이미 있는 눈 감기 표현도 원본 타이밍에 맞춰 쓰려 했다.
- **도구가 준 것:** README `What it does`: “a rotate track per mapped bone, a translate track on the hip”. 실제 dance는 25 tracks이고 eyes/mouth가 없으며, idle에는 eyes scaley가 있다.
- **있었으면 했던 것:** 리타깃 결과에서 원래 모션의 어떤 표정/보조 트랙이 사용되지 않는지 목록을 출력하고, 별도의 측정된 이벤트 타임라인을 합성하는 방법을 안내했으면 한다. body-17에 없는 눈꺼풀을 자동으로 안다고 추측하는 기능은 원하지 않는다.
- **비용:** 얼굴 확대 시트·프레임 관찰·수동 키 작성, 대략 2분. 기존 scale/easing으로 다섯 구간을 추가했다. 입모양은 새 그림이 필요해 남겼다.

@rig-c/parts는 README와 제공된 생성 리그를 참고했으며 이번에는 생성 CLI를 실행하지 않았다. 이번 실행에서 재현하지 않은 생성기 문제를 불만 항목으로 만들지 않았다. ffmpeg 옵션 실패와 시트 glob 오류는 각각 실행 환경/응시자의 실수이므로 세 패키지의 결함 목록에 넣지 않았다.
