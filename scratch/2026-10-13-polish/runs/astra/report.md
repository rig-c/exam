# 아스트라 — 춤추는 리그 손질하기 (1회차)

응시명은 사용자 프롬프트의 **아스트라**를 그대로 사용했다. 하위 에이전트 **0회**. 이 문제와 이전 풀이를 보지 않은 이 대화에서 직접 읽고 수행했다. 시작 시 전역 운영지침과 다른 리그 시험에 관한 일반 메모리 요약은 이미 컨텍스트에 있었지만, 이 문제의 해답/풀이 보고는 없었다. 다른 폴더·레포·세션·메모리 파일은 조회하지 않았다. 로컬 작업이며 Git·브릿지·원격 실행·업로드를 하지 않았다.

## 결과

[최종 데모](after/clip-audio.mp4)는 원본과 같은 **왼쪽 영상 | 오른쪽 리그, 648×480, 24fps, 313프레임, 13.041667초**다. 음악은 제공된 audio.mp3를 0초부터 사용하고 영상·음성 스트림의 start_time=0을 확인했다.

고친 것은 오른손의 앞뒤 관계, 눈 감기 다섯 구간, 치마의 좌우 퍼짐/기울기, 지지 발의 수직 높이, 정강이 메시 연결이다. **원본 춤 전체를 재현했다고 판정하지 않는다.** 특히 양발 접지·수평 미끄러짐, 깊이 방향 무릎 굽힘, 입모양·단축된 팔·올라간 재킷 그림은 남았다.

## 고친 것과 근거

### 팔 — A1

f19–60(0.792–2.500초)의 오른팔은 등 뒤에 남겨야 한다. K0 오른팔 attachment를 연장하고, 몸통·왼팔의 기존 선택을 유지했다. 오른팔 월드 각도는 `drawn ±5°` 내로 제한했다. 숨김 시험에서는 팔꿈치까지 사라졌으므로 버렸고, 최종적으로 아래팔을 허용 범위 안쪽으로 4프레임에 걸쳐 돌려 조각의 가는 잔선을 몸 안에 가렸다.

방법은 **@rig-c/pose README `Alternate drawings`의 slots/hides/drawn/turn**, **rigc AUTHORING §4.4 attachment**에서 읽었다. 최종 geometry상 최대 |turn|은 **5.000177°**, 문서에 명시된 키 반올림 허용 0.001° 안이다. 앞에 보이던 손은 사라지고 팔꿈치 실루엣은 남았다.

![f30 전후: 원본 | 전 | 후](evidence/compare-f030.png)

`after/map.json`은 최초 리타깃의 출처로 보존했다. 최종 수리는 `after/motion.json`이며 map을 다시 retarget한다고 수리본이 재생성되는 것은 아니다. 추가 수리 기록은 arm-repair.json과 arm-occlusion.py에 있다.

### 발과 몸 — L1·B1, 부분 개선

원본 점프 구간의 발목 상승분은 남기고, 나머지 구간에서 두 신발 중 낮은 쪽의 바닥을 첫 프레임 높이에 맞추는 root translatey 키를 추가했다. 기준은 **AUTHORING §4.4의 setup-relative translate**, 측정은 render --geometry와 pose.json이다. 점프 창 f85–94,175–184,265–275와 접지 기준은 관찰에 따른 편집 선택이다.

| 측정 | 전 | 후 |

| 점프 상승분이 0인 프레임들의 최소 신발 바닥 범위 | 69.444677 | 0.000332 |
| 목표 최소 바닥 대비 최대 오차 | — | 0.000188 |

### 정강이 — L2

두 다리를 가로지르는 삼각형 10·11의 텍스처 픽셀 알파가 모두 0임을 측정했다. 단순 삭제는 `the triangles' outline is not one closed loop`로 거부됐다. **AUTHORING §3.4 hull, §5.1 오류 안내**를 따라 경계를 걷고 UV·weights·triangles를 함께 재번호화하여 두 메시로 나눴다.

- 오른쪽 142정점/218삼각형, 왼쪽 144정점/224삼각형.
- 기존 216프레임의 shins fold → **최종 313프레임에서 모든 13개 메시 fold 0**.
- 실제 그림을 잃지 않는 투명 연결만 없앴다. 원래 두 삼각형이 피부를 뚫고 보였다고 주장하지 않는다.
- 메시 수 증가에 맞춰 meshSlots 예산 12→13을 명시했고, meshTriangles 예산은 444 그대로다.

### 치마 — C1, 부분 개선

검정 실루엣에서 폭, 골반 대비 좌우 치우침, 양쪽 밑단 높이 차이를 측정했다. 처음 ROI는 올라간 옆단을 잘랐으므로 증거 이미지를 보고 범위를 넓혔다. 움직임은 허리선에서 0, 밑단에서 크게 적용하며 **AUTHORING §4.11**에 따라 각 bone influence의 bind-space 쌍으로 변환해 313개 deform 키를 썼다. 기존 아홉 physics 제약과 수치는 유지했다.

f96–264의 정규화 검정 실루엣 폭 MAE는 **0.113536 → 0.077282, 약 31.93% 감소**다. 실제 화면에서도 f138의 왼쪽 퍼짐과 f192의 오른쪽 퍼짐이 늘었다. 이는 동일 계측 방식에 기반한 보조 수치이며 독립된 인간 품질 점수가 아니다. 깊이 방향의 주름 뒤집힘/가려진 면까지 복원한 것은 아니다.

### 눈 — H1

원본에서 확인한 눈 감기 다섯 구간에, 입력 idle에 이미 있던 **eyes scaley 0.12와 shut/open easing**을 적용했다. **AUTHORING §4.4–4.5**의 group/scale/key 규칙을 사용했다. f18·138·174·234·258에서 렌더된 눈 뼈의 상대 면적 배율 0.12, f0·288에서 1을 확인했다. 정확한 키는 blink-timing.json에 있으며 경계 보간은 수동 편집값이다. 모든 찡그림과 윙크를 복원한 것은 아니다.

## 검증과 한계

- 최종 기본 spine 프로파일: **22 measured, 22 passed, 0 failed, 16 skipped, 14 not in profile**.
- 추가 rig-play 프로파일: **30 measured, 30 passed, 0 failed, 22 skipped**.
- 후자는 deform **313키·312보간 구간·32,552삼각형**을 측정했고 collapse 0이다.
- 최종 render: **313프레임, 13개 메시 fold 0**, rigc core poser.
- 설치된 공개 core entry의 공급자는 **model**이다. **A00_ROUNDTRIP_PARSE는 SKIP**이며 공식 spine-core 파서를 실제 실행했다고 주장하지 않는다.
- 전후 viewport를 공통 월드 좌표/배율로 재배치했다. 원본 영상은 외부로 내보내지 않았다.
- 각도·접지 수치는 JSON 키 자체가 아닌 최종 geometry에서 확인했다. 그림은 주요 전환/극점 이미지로 확인했으며 모든 픽셀의 미학적 정답을 보증하지 않는다.

근거: [build report](after/build-report.json), [rig-play report](after/rig-play-report.json), [verification](after/verification.json), [접지 수치](after/comparison-metrics.json). 재현은 시험 폴더에서 `bash run/after/reproduce.sh`로 한다. Python Pillow와 ffmpeg가 필요하다.

## 남은 것과 필요한 그림

- **A2:** K1에서 양팔을 머리 뒤로 더 붙이는 변형. report의 오른쪽 아래팔은 기존 그림보다 -36.438° 방향을 요구해 -20° 제한에 걸린다. 그 자세의 팔꿈치/손목 위치를 기준으로 팔과 재킷을 함께 다시 그려야 한다. 제한을 풀면 기존 그림을 틀어 문제를 감출 뿐이다.
- **A3:** f31–36의 얼굴 옆 팔을 카메라 방향으로 단축한 세트, f264–275의 손을 내미는 동작에서 V사인으로 넘어가는 중간 세트. 손바닥·손가락 방향과 팔의 보이는 길이를 함께 제공해야 한다.
- **H2:** 벌린 입, 다문 입, 오므린 입, 미소를 동일 입 기준점으로 그린 교체 그림. 기존 작은 입 이미지를 늘려 이 표정을 지어내지 않았다.
- **C2:** 양팔을 머리 뒤로 올렸을 때 재킷 밑단이 올라가고 허리가 드러나는 몸통/소매 묶음, 한 팔을 높이 든 몸통 변형. 현재 텍스처에 없는 살/접힌 천을 보간으로 발명하지 않았다.
- **L1·B1:** 양발 접지와 착지 압축은 남는다. 정면에서 깊이 방향으로 굽힌 무릎·발목 조각, 그리고 지지 상태를 명시한 타깃과 IK/도달 불가능 판정이 필요하다. 현재의 한 발 높이 보정을 완성으로 부르지 않는다.
- **C1:** 투영 실루엣은 개선했지만 펼쳐진 주름의 새 면과 천의 깊이는 없다. 그 각도의 치마 그림이 있어야 더 정확히 표현할 수 있다.

## 도구가 했어야 할 것

입력만으로 가능한 것: 완전히 투명한 교차 다리 연결의 경고/분할 제안(T1), 기존 idle 표정 트랙 중 retarget 결과가 사용하지 않는 것의 목록, 선언된 접지 목표에 대한 잔차 검사, 동일 viewport 전후 렌더. 영상 없이는 구분할 수 없는 오른손의 앞뒤와 입모양을 body-17만 보고 자동으로 안다고 요구하지 않는다.

[tools.md](tools.md)의 실제 항목 제목:

1. 접지 상태를 표현하는 입력과 수리가 없다 — rig-pose
2. 투명 다리 연결을 끊은 뒤 분할까지 수작업이다 — rigc
3. 전후 렌더의 고정 월드 뷰포트를 지정할 수 없다 — rigc
4. 리타깃이 놓친 보조 표정 트랙을 알기 어렵다 — rig-pose

## 일지·비용·응시 기록

일지 **20항목**, 4행이 `WTF?:`로 시작하는 것 **5항목**(3·4·5·12·16). 단위 관련 항목은 **머리 4, 팔 4, 몸 2, 다리 4, 옷 4**, 공통 준비/검증/보고 8이다. 여러 단위의 공통 증거 항목은 각 단위에 중복 집계했다. 정확한 ID는 journal-counts.json에 있다. **부대 0회, 외부 도움 0회**.

가장 시간을 쓴 세 작업은 다음과 같다. 세부 스톱워치를 두지 않아 분 단위는 파일 생성 시각과 실제 명령 흐름을 바탕으로 한 근사다.

1. **단위별 비교·증거 추출·실루엣 계측**, 대략 6분(10:53–10:59 UTC). render --help, AUTHORING §8.2–8.3, pose README의 alternates. ROI가 옆단을 자른 것을 눈으로 발견해 계측을 다시 했다.
2. **전후 재렌더·합성·팔 이음새 재검증**, 여러 렌더를 포함해 대략 5분 이상. render --help의 `--hide`와 frames.json.viewport. 숨김안은 팔꿈치를 없애서 거부하고 각도 범위 안에서 다시 손질했다.
3. **수리 스크립트·가중 deform·정강이 분할**, 대략 3분의 집중 구현과 추가 확인. AUTHORING §3.4·4.4·4.11, `outline is not one closed loop` 오류. 첫 단순 삭제안은 실패했다.

초기 head 시트가 54개라고 한 것은 ffmpeg의 문제가 아니라 glob에 head-reference.png를 포함한 내 실수였다. Entry 19에서 정정하고 숫자 프레임 53개로 시트를 다시 만들었다. 실패/정정 기록은 삭제하지 않았다.

정확한 토큰 사용량은 실행 환경에서 제공되지 않아 **usage.json을 만들지 않았다**. 시간의 원시 시작·종료 값은 transcript.md의 첫 줄과 마지막 줄이다. 초기 파일작성은 명령 요약으로 기록했고, 작업 스크립트 원문은 run/에 남겼다. 모든 후속 실행 명령은 do.py가 출력 말미와 종료 코드를 기록했다.
