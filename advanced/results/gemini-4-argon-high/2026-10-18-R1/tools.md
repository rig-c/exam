# What the tools were missing

## Eye-line head mapping couples non-periodic vertical nod into head.rotate and breaks loop and jitter
- **I was trying to:** Map the `head` bone to the sequence's horizontal eye line (`"joints": ["r_eye", "l_eye"], "aim": ["eye_r>eye_l"]`) as shown in `node_modules/@rig-c/pose/README.md` under `## The map: rig-pose-map/1` while keeping `jitter` (`<= 1.1x` of the mapped joint pair) and `loop` (`<= 1.0°` between cycle 1 and cycle 7) within the pass table bars.
- **The tool gave me:** `node_modules/@rig-c/pose/README.md` (`## The map: rig-pose-map/1`, line 314) recommends: `"a>b" — the direction from point a to point b; right for a head, turned by its eye line: { "bones": ["head"], "joints": ["r_eye", "l_eye"], "aim": ["eye_r>eye_l"] }`. Meanwhile, line 110 (`## What it does`) states: `"When a head chain carries the eye line (r_eye → l_eye), the eyes' vertical travel against neck in the reference, scaled into the rig's units, keys a vertical translate nod channel on the head bone (#111) clamped within ±2% of the setup neck length (head − neck, #181), while on sequences where that clamp acts, the clamped vertical nod (clampedY) is coupled in phase into face.pitch's dial (+2.8°/unit, mapped through face.pitch.range) and the head bone's rotate track (+1.6°/unit, #190, #205)"`. Running `grade.py` on that map produced `FAIL jitter ... trunk+head 1.277x sequence (0.918 vs 0.719 deg/f^2, chest,head) [bar <= 1.1]` and `FAIL loop ... cycle 1 vs cycle 7: max keyed-bone angle difference 1.3809 deg (head, cycle frame 13) [bar <= 1.0]`.
- **What would have helped:** Either (a) wrapping the nod detrending window periodically on looped sequences (`cleaned.params.loop: true` / `"travel": "in-place"`) and providing a flag to disable coupling `clampedY` onto `head.rotate` when no `face.pitch` dial is used, or (b) noting in `## The map: rig-pose-map/1` that `r_eye -> l_eye` couples vertical nod into `head.rotate` whereas `r_ear -> l_ear` keys pure 2D head roll.
- **Cost:** About 3 minutes to diagnose why `head` failed both `jitter` and `loop` on an exact 32-frame repeated sequence; got there in the end by switching `head.joints` to `["r_ear", "l_ear"]`.

## Leg foreshortening range is only reported after a run with --leg-scale
- **I was trying to:** Choose `--leg-scale <min,max>` bounds for `rig-pose retarget` so that no lifted leg segment in `inputs/pose/sequence.json` would clamp at the lower bound.
- **The tool gave me:** On the baseline run without `--leg-scale`, `rig-pose retarget` printed `FEET read, not planted (no --plant-feet): leg length (median hip → ankle) r 392.8px, l 405.4px; 16 support span(s), 8 change(s) of support, 0 jump(s), 14 step(s)` and wrote `"legScale": null` in `run/before/report.json`. Only after running with `--leg-scale 0.6,1.05` did `report.json` populate `legScale` showing `"bone": "leg_r1", "joints": ["r_knee", "r_ankle"], "ratio": { "min": 0.4510805115688025, "median": 0.8407601650278399, "max": 1.008897106998424 }` and 7 clamped runs.
- **What would have helped:** Printing each mapped leg segment's picture-to-straight length ratio (`min`, `median`, `max`) in the `FEET` readout and `report.json` even when `--leg-scale` is not passed, so the author can read the exact minimum (`0.4511`) from the first run instead of guessing `0.6` first.
- **Cost:** About 1 minute (one extra `rig-pose retarget` run between Entry 11 and Entry 13); got there in the end by reading `legScale[1].ratio.min` from `run/after/report.json` and re-running with `--leg-scale 0.45,1.05`.

## CLI flag naming mismatch across tools for sequence and animation inputs
- **I was trying to:** Run `rig-pose retarget` for the first time after reading `PROBLEM.md` and `tools/grade.py`.
- **The tool gave me:** `rig-pose retarget: unknown flag --sequence; the flags are --rig, --map, --pose, --out, --name, --person, --base-motion, --images, --min-score, --smooth, --flip, --short, --bends, --bend-tolerance, --switch-tolerance, --switch-min, --switch-at, --profile, --build, --render, --report, --camera, --leg-scale, --idle, --merge, --reduce, --reduce-hip, --stance, --floor, --coco, --plant-feet, --carry-idle, --raised-by-head (rig-pose --help)` (exit code 2).
- **What would have helped:** Accepting `--sequence` as an alias for `--pose` and `--animation` as an alias for `--name` in `rig-pose retarget` (matching `rigc render --animation` and `grade.py --sequence`).
- **Cost:** Under 1 minute (one failed invocation in Entry 2); got there immediately from the error message's flag list.
